# Deka 0.11.0 — Desktop DJ

Дата: 30 октября 2026, Москва. База: `feature/v0.10.0-sets`, `4eea9907b5fb74a1b6360c384188c4b9c6ff33f5` (0.10.7).
Рабочая ветка: `feature/desktop-dj-0.11.0`. Текущий запрос Алекса переносит приоритет на Windows. Android UI не перерабатывается; общие изменения проверены его существующими тестами.

## Реализовано

- В существующей Windows-оболочке Tauri новый режим `DJ · A/B`. Прежние плеер, EQ, VK, сеты, библиотека и её последние исправления 0.10.7 сохранены.
- Одна библиотека локальных файлов для плеера и DJ. Выбор файлов в DJ не запускает обычный плеер. Поиск по всему списку; виртуальная отрисовка ограниченного числа строк. Явные кнопки «В A» / «В B».
- Отдельные Audio и состояния A/B: загрузка без автозапуска, play/pause, seek, время/остаток, ошибка, транспортный CUE. Замена играющего трека требует подтверждения. Конец в DJ останавливает деку, обычный режим сохраняет очередь.
- Темп ±8% меняет высоту звука, reset, nudge ±4% при удержании (отпускание/отмена/потеря фокуса возвращает темп). Ручной BPM и TAP, без выдуманного автоанализа. Колесо/стрелки на диске перематывают на 1 секунду; это не scratch.
- LOW/MID/HIGH, уровень каждого канала, равномощный crossfader, master, реальные пиковые измерители A/B/master. Общий AudioContext. Загрузка нового трека освобождает прежний media/source; его поздние события игнорируются. Object URL принадлежит общей библиотеке и отзывается при удалении файла, без сохранения временных адресов в постоянное хранилище.
- Вход в DJ приостанавливает одиночный плеер/VK, выход приостанавливает обе деки. Открытие поиска и изменение размера окна не пересоздают аудиоисточники. DJ-клавиши не вызывают старый транспорт.

## Аудиограф и границы

Локальное media → LOW/MID/HIGH → channel gain × crossfader × 0.25 → master → compressor → ограничение амплитуды WaveShaper ±0.98 → измеритель → выход. Канальные измерители находятся после фейдера/crossfader. Коэффициент 0.25 даёт запас −12.04 dB; параметры gain/EQ/master сглаживаются с постоянной времени 20 мс. Компрессор сам по себе не объявляется brickwall-лимитером. WaveShaper обеспечивает цифровой потолок в выборках; при сильном перегрузе возможны искажения, intersample/аналоговый true-peak не гарантируется.

Crossfader: x от −1 до 1, A=cos((x+1)π/4), B=sin((x+1)π/4). Темп — playbackRate с отключённым preservesPitch. CUE устанавливается на паузе, при игре останавливает и возвращает к точке.

Локальные файлы не уходят на сервер; поддержка форматов зависит от WebView2. WAV проверен синтетическими файлами. MP3/FLAC/OGG/M4A/AAC/Opus принимаются выборщиком, но требуют проверки кодеков целевой Windows. После перезапуска нужно выбрать файлы снова. Полная библиотека не декодируется в память: media читаются по мере воспроизведения, метаданные освобождаются после чтения.

VK остаётся отдельным обычным плеером. Нет двух VK-потоков, headphone cue, автоматического sync/BPM, waveform, винилового scratch или записи микса.

## Фактическая проверка

Выполнены `npm test` (20 модульных проверок плюс синтаксис/версии/генератор Android) и прежние `tests/browser.py` (78 сценариев). Проверки используют синтетическую DOM-разметку VK, без живой сессии.

`tests/desktop_dj.py` проверяет настоящий WebAudio-выход Chromium на двух WAV 440/660 Hz: центр/края crossfader, независимость gain/EQ, master, фактический сдвиг частоты при tempo/nudge, 60 секунд одновременного продвижения двух media, CUE, отказ от замены, search/resize, ended/error/rapid reload, ограничение пика с усиленным EQ, поиск последнего из 1500 треков, выход в обычные сеты. Метод: DFT с окном Hann, 32768 отсчётов при 48 kHz после выходного аудиографа. Это измерение цифрового выхода браузера, не захват звуковой карты Windows.

В измерении первого прогона: в центре амплитуды 440/660 Hz 0.10482/0.10482; слева 0.14824/7.53e−9; справа 7.56e−9/0.14824. Требование подавления >40 dB выполнено с большим запасом; точный предел численной оценки не означает такую же изоляцию аналогового устройства. MID −12 dB в A уменьшил её составляющую 0.10482→0.06566 при неизменной B. Отчёты и снимок сохраняются в `test-output/`, CI прикладывает их как `browser-regression-results`.

Windows exe/installer собираются Actions после тестов в артефакт `deka-windows`. Наличие кода и браузерных тестов не заменяет успешный Windows build; результат конкретного запуска нужно проверить в Actions. Публикация релиза и слияние main не выполняются. Эта ветка не собирает новый APK.

## Приёмка на компьютере Алекса

1. Запустить Deka.exe → `DJ · A/B` → `＋ Файлы`, выбрать два разных локальных трека.
2. Первый «В A», второй «В B». Убедиться, что загрузка не начинает воспроизведение.
3. Запустить обе деки, проверить 60 секунд одновременной игры. Pause/seek B не меняет A.
4. На паузе B поставить CUE, запустить B, нажать CUE: остановка/возврат. Проверить темп и nudge.
5. Перевести crossfader A→B, проверить независимые EQ/уровни и общий master; вернуть в центр.
6. Проверить окно VK: вход, полный список, выбор последних треков, сеты/продолжение. Затем вернуться в DJ с локальными файлами.

Физическая Windows, WebView2, аудиоустройство, живой VK и физический Android в этой среде не проверены. Следующий этап — приёмка Windows и исправление замечаний, затем согласование переноса DJ-контролов Android.
