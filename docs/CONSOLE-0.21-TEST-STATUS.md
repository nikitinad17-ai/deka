Дата: 10 ноября 2026. Изменения по скриншотам пользователя 25171.jpg и 25172.jpg.

Все 16 заданий unit, поверхностей, регрессий и сборок прошли; нативный Android
проверен [отдельным успешным прогоном](https://github.com/nikitinad17-ai/deka/actions/runs/42764959311)

прогона (происхождение, Android, упаковка) завершились успешно; его тестовый коммит —
`a87272c8f9157c70c72854c1cee824311006014b`. Основной прогон не целиком зелёный:
первоначальный нативный тест завершился ANR, а упаковка была пропущена; подробности ниже.

## Что исправлено

- Возвращена компактная зеркальная вертикальная компоновка: EQ / пластинка /
  список и эффекты; B зеркальна A, микшер между деками.
- Выбор трёх пультов сохранён. Кнопки и регуляторы получили объём, подсветку
  выбранного состояния и видимый отклик на нажатие.
- Поворот обратно в портрет сохраняет DJ; эффекты в портрете видны постоянно.
- Исправлены найденные при визуальной приёмке обрезания значений FX и строки исполнителя.
- В узком горизонтальном окне после вычета системных панелей Play/Next/CUE и обе
  пластинки остаются видимыми. Сохранена поверхность скретча не меньше 100 CSS px.
- Активный «Автомикс» в светлом Editorial получил контрастный фон.
- Нативный контейнер Android учитывает системные панели и вырезы по четырём краям,
  передаёт WebView обнулённые уже учтённые отступы, сохраняя обработку клавиатуры.

## Окружение проверки

В первой попытке итогового прогона Desktop-тест не стартовал: загрузка пакетов
Ubuntu (`azure.archive.ubuntu.com`) зависла и задание достигло лимита 12 минут.
Перезапущено только это задание с зависимыми сборками, без изменения исходников
или ослабления проверок. Остальные 13 заданий уже завершились успешно.

На первом запуске финального нативного стенда Android зафиксирован ANR при
получении FocusEvent (5 секунд), ещё до монтирования тестового интерфейса:
CPU TOTAL 99%, load 22.89 на двух виртуальных ядрах, CPU pressure avg10 89.47%.
Это свидетельствует о перегрузке стенда при первой настройке Android, но не
доказывает отсутствие проблемы холодного запуска приложения на устройствах.
Стенд теперь ожидает измеряемого запаса CPU перед запуском, использует 4 ядра /
4096M RAM и отдельно проверяет весь журнал на ANR приложения. Таймаут ANR Android
не увеличен, диалог зависания не подавляется и не закрывается тестом.
Повторная проверка неизменённого APK в этом окружении прошла 77/77 без ANR.
Параметры успешного отдельного стенда перенесены в основной workflow; последующая
правка отчёта и параметров CI не меняет исходники или файлы приложения.

Нативный стенд использует API 36, Google APIs x86_64, экран 720×1600 / density 320
и программный рендерер Mesa (`lavapipe`). Ранние попытки на SwiftShader завершались
вместе с процессом эмулятора; успешность на физическом Xiaomi из этого не следует.

## Наблюдение при повторном прогоне

В первой попытке финального прогона `mp3_transport` один раз достиг лимита
ожидания 5 секунд на первом ускоренном переходе. Причина по сохранённому логу
не установлена. Повторный запуск того же коммита без изменения теста прошёл
15 проверок: 11 последовательных переходов, конец очереди, быструю замену,
устойчивую паузу и отсутствие ошибок JavaScript. Предыдущий полный прогон
`42492695708` также прошёл этот сценарий. Сбой не объявляется исправленным;
при повторении на устройстве нужны отчёт и последовательность действий.
